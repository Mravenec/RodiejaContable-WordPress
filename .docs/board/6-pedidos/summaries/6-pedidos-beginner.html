Basic concepts (read once)

Unified WordPress tree — Like a real WP/DDEV project: web/ is the docroot. Custom code lives in wp-content/plugins and mu-plugins — not in numbered 0/1/2 app folders.

Plugin architecture — Inside the plugin only: Contracts → Repositories ($wpdb) → Services → Controllers with constructor DI.

Native only — hooks/filters, REST API, $wpdb/dbDelta, capabilities, nonces, sanitize/escape, WP-CLI, Composer PSR-4.

GATE_HTTP — REST/admin smoke proves the contract before dependents proceed.

Worktrees — After every claim, isolate with node .ai/scripts/worktree-add.mjs <ISSUE_ID>.

FAQ for beginners

Why no 0.database / 1.plugin folders?
Those mimic a multi-app Spring harness. A real WordPress site is one docroot with plugins inside wp-content.
Where does DI/SOLID live?
Inside the custom plugin under web/wp-content/plugins/<module>/src/.
Is Composer allowed?
Yes for PSR-4 and WPCS/PHPUnit — not for Laravel/Doctrine app frameworks.
